`debug` workflow (slice 3, S3-3), which closes the backlog item "healing existing scripts". It runs a chosen part of the repo's own suite and classifies each failure as selector, timing, data, flake, environment or defect. It proposes only the fixes each kind allows, in the test files it showed the model, as one diff that waits for the person's own yes. Each file is written only if it is unchanged since it was read, then the tests run again and, once green, run again to show they are stable. A defect or an environment failure is reported and nothing is changed. A declined change is kept as a diff in `debug-report@1`. A fix may no longer change the texts of an element that a check like `toBeVisible()` checks; this applies to `scripts` fixes too.
