Repo paths are masked like any other text a model sees. A test file named after a person (`tests/users/marie-curie.spec.ts`) reaches the model, the run's reports and its artifacts as `tests/users/<PATH_CCTXRDPWVM_1>.spec.ts`, and Agent-QA finds the real file again when that path comes back (a read, an edit, a test run, a type check, a pull request). Each part of a path is masked alone, with its suffix kept (`.spec.ts`, `.page.ts`, `.feature`). The token is a keyed hash of the name (a key derived from the vault key), so the same file has the same token in every run on the machine: an audit's finding still names the file in the refactor, and a run-tests selection in debug. This covers the framework listing, the framework profile, the test command shown for approval, test results and failures, type errors, related feature files and refusal messages. Limits: the profile's folder itself is shown as it is; an import inside a file can name a masked file differently from its path; a review glob is matched against the shown paths, so a glob that spells a masked name matches nothing; tokens differ between machines (CI and a laptop have different vault keys).
